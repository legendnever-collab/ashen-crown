## 1. 한도
- GitHub는 **100 MiB가 넘는 파일을 받지 않습니다.** 게임은 HTML 한 파일이라, 이 파일이 한도 안에 있어야 합니다.
- v2.2.0은 63.7 MiB였습니다.
  - 그림이 46.7 MB입니다.
  - 그림을 HTML 안에 글자(base64)로 넣으면서 3분의 1이 더 붙습니다.
  - 코드는 1.8 MB뿐입니다.

## 2. 한 일

| 방법 | 내용 | 결과 |
|---|---|---|
| **그림을 AVIF로** | 초상 · 일기토 · 지도 그림은 화질 60, 실내 · 거점 · 세계지도는 65. 해상도는 그대로 | 406장, 45.5 → 31.9 MB |
| **크기 예산** | 빌드마다 종류별 크기를 `build/size-report.json`에 남김. **80 MiB 넘으면 경고, 90 MiB 넘으면 빌드 실패** | 63.7 → **45.8 MiB** |

| **안내문** | AVIF를 못 여는 브라우저(Safari 16.4 이전)에서는 위에 안내가 뜸 | |

**그림 확인 방법**
- 그림마다 지금 WebP와 비교합니다(SSIM: 같으면 1).
  - 초상 · 일기토 · 지도 그림: 0.975 미만이면 화질을 5씩 올립니다.
  - 실내 · 거점 · 세계지도: 0.97 미만이면 화질을 5씩 올립니다.
  - 80까지 올려도 모자라면 WebP로 남깁니다.
- 결과: 406장 모두 기준을 넘었습니다.
  - 초상 2장, 일기토 4장, 실내 11장은 화질을 올렸습니다.
  - 가장 낮은 값은 실내 0.970, 가장 높은 평균은 지도 그림 0.996입니다.
- 비교 그림: `docs/v2.2.1/screenshots/avif-compare-*.png`(왼쪽 WebP, 오른쪽 AVIF, 실제 크기)
  - 초상과 결정타 컷은 구별이 안 됩니다.
  - 실내 바닥과 거점 땅의 결이 조금 부드러워졌습니다. 나란히 놓아야 보이는 정도입니다.
- 그림을 여는 시간: 큰 그림 394장을 한꺼번에 열 때 WebP 1.75–1.79초, AVIF 1.49–1.55초입니다(`docs/v2.2.1/evidence/decode-time.json`).

## 3. 저장소가 커지는 것 막기
- **빌드는 git에 올리지 않습니다.**
  - 개발 중 빌드는 `build/Ashen_Crown.html`로 나가고, git이 무시합니다.
  - 릴리스 후보를 묶을 때(`scripts/package.py`)만 `index.html`과 `releases/Ashen_Crown_v<버전>.html`로 복사해 커밋합니다.
  - 지금까지는 빌드할 때마다 60 MB짜리 파일이 저장소에 쌓였습니다(124번).
- **CI**
  - 시험 전에 직접 빌드합니다.
  - `verify-release.py`는 묶기 전에는 건너뜁니다. 묶은 뒤에는 커밋된 HTML이 새로 빌드한 것과 같아야 합니다.

## 4. 지난 버전 보관 (사용자가 한 번 실행)
- 이 작업 환경에서는 **GitHub 태그와 Releases를 만들 수 없습니다**(403). 그래서 실행만 하시면 되도록 준비해 두었습니다.
- 준비한 것
  - `releases/ARCHIVE.json`: 지난 28개 버전의 파일, 크기, SHA256, 그 HTML을 묶은 커밋
  - `scripts/archive-releases.mjs`와 GitHub Actions 「Archive old builds」(수동 실행)
    - 버전마다 태그 `v<버전>`과 Release를 만들고 HTML, Source.zip, 시험 보고서, 체크섬을 올립니다.
    - 이미 있는 Release(v0.3.1 · v0.3.3 · v0.4.0 · v0.5.0 · v0.6.0)에는 빠진 파일만 더합니다.
  - `scripts/fetch-releases.mjs`
    - 마이그레이션 시험이 옛 버전을 쓸 때, 저장소에 없으면 Release에서 받아 SHA256을 확인합니다.
    - REST API를 쓰므로 CI와 이 환경 모두에서 동작합니다(v0.3.1로 실제 확인).
- **순서**
  1. v2.2.1을 병합합니다.
  2. GitHub에서 **Actions → Archive old builds → Run workflow**를 누릅니다.
  3. 끝나면 다음 버전에서 저장소의 지난 HTML · Source.zip(약 1.85 GB)을 뺍니다. 시험은 Release에서 받아 씁니다.
- 이미 저장소 기록에 쌓인 2.2 GB는 기록을 다시 써야만 줄어듭니다. 되돌릴 수 없는 일이라 하지 않습니다.

## 5. 앞으로의 예상

| 시점 | 지금 방식 그대로였다면 | v2.2.1 방식 |
|---|---:|---:|
| 지금 | 63.7 MiB | **45.8 MiB** |
| 게임 완성(ACT II–IV 큰 맵, 부장 · 구출 장수 초상, 그림팩 H2, 작은 마을) | 약 75–80 MiB | **약 52–55 MiB** |

- **예비 방법:** 그림을 글자로 넣는 방식을 base64에서 base-122로 바꾸면 −14%(지금 기준 −8.9 MB)입니다. 게임을 열 때 되돌리는 처리가 필요해, 80 MiB 경고가 뜰 때만 씁니다.
- **쓰지 않는 방법:** 해상도 낮추기(초상이 최대 500px로 그려져 고해상도 화면에서 흐려짐), 파일 나누기(「HTML 한 파일로 실행」이 깨짐).

## 6. 그림을 들여올 때

  - 원래 들여오기 기록(`*-import-log.csv`)은 WebP 이름과 해시를 그대로 둡니다.
